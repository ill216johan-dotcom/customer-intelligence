# Customer Intelligence System (CIS) — Полная спецификация проекта

## 1. Суть проекта
**Customer Intelligence System (CIS)** — это AI-платформа для автоматизации сбора, анализа и управления знаниями о клиентах в сфере фулфилмента. Система агрегирует данные из созвонов, чатов и внешних CRM/WMS систем, превращая разрозненную информацию в единый "цифровой профиль" клиента с возможностью интеллектуального поиска (RAG) и проактивного уведомления о рисках (Churn Prediction).

## 2. Архитектура системы

### 2.1 Технологический стек
- **Backend:** FastAPI (Python 3.11) — высокопроизводительный API.
- **Frontend:** Next.js 14 (App Router) + TailwindCSS — современный интерфейс в стиле Notion/NotebookLM.
- **Database:** PostgreSQL 16 + **pgvector** — хранение структурированных данных и векторных эмбеддингов для поиска.
- **Queue/Workers:** Celery + Redis — фоновая обработка тяжелых задач (транскрипция).
- **AI/ML:**
  - **STT:** OpenAI Whisper (self-hosted) — локальная транскрипция аудио без затрат на API.
  - **LLM:** GLM-4 (ZhipuAI) — саммаризация, анализ тональности и RAG-чат.
  - **Embeddings:** GLM Embedding-2 — создание векторных представлений текста.
- **Automation:** n8n — интеграционный клей для внешних сервисов (Telegram, Bitrix24).

### 2.2 Структура данных
Система строится вокруг сущности **Customer**, к которой привязываются:
- **Calls:** Аудио, транскрипты, саммари, ключевые точки.
- **Messages:** История переписки (Telegram, Email, WhatsApp).
- **Notes:** Ручные заметки менеджеров.
- **Alerts:** Автоматические уведомления о рисках (Health Score).

## 3. Функциональные модули

### 3.1 Конспектирование созвонов (Jitsi & Manual)
- **Запись:** Интеграция с Jitsi через Jibri (планируется) или ручная загрузка аудиофайлов.
- **STT (Speech-to-Text):** Whisper обрабатывает аудио, разделяя его на спикеров (диаризация).
- **AI-Анализ:** GLM-4 создает:
  - Структурированное саммари (2-3 предложения).
  - Ключевые пункты обсуждения.
  - Список задач и договоренностей (Action Items).
  - Выявление "болей" клиента.

### 3.2 Анализ переписок (Telegram Sync)
- **Сбор:** Ежедневная выгрузка сообщений из чатов через Telethon (userbot) или n8n.
- **Саммаризация:** Группировка сообщений по темам и создание краткого отчета за день/неделю.
- **Тональность:** Анализ эмоционального фона общения (позитивный/негативный/нейтральный).

### 3.3 Единый профиль клиента (360° View)
- Хранение информации: товары, маркетплейсы, история работы.
- Блок "Боли и Конфликты": автоматическое наполнение на основе анализа созвонов.
- Хронология: лента всех взаимодействий в одном месте.

### 3.4 RAG-чат (Интеллектуальный помощник)
- Возможность задать вопрос: *"Какие были проблемы с отгрузками у этого клиента в прошлом месяце?"*.
- Система ищет по векторной базе (pgvector) среди всех созвонов и сообщений.
- Ответ дается со ссылками на первоисточники (конкретные созвоны или даты переписки).

### 3.5 Мониторинг рисков (Churn Prediction & Alerts)
- **Health Score:** Комплексная оценка состояния клиента на основе:
  - Частоты коммуникаций (Engagement).
  - Тональности сообщений (Sentiment).
  - Операционных показателей из WMS (объем отгрузок, брони).
- **Алерты:** Автоматические уведомления при:
  - Резком снижении объема отгрузок ("потенциальный съезд").
  - Ухудшении тональности общения.
  - "Много броней" (риск переполнения склада или фейковых заказов).

## Принятые решения (ADR)

### ADR-001: Whisper вместо Yandex SpeechKit
**Дата:** 2026-02-17
**Решение:** Использовать self-hosted Whisper
**Причина:** 10ч аудио/день × 22 дня = 220ч/мес → ~25,000 руб на Yandex vs 0 руб на Whisper
**Компромисс:** Требуется мощный сервер (16GB RAM)

### ADR-002: GLM-4 вместо Claude
**Дата:** 2026-02-17  
**Решение:** GLM-4 API для саммаризации
**Причина:** Бюджетные ограничения
**Компромисс:** Качество может быть чуть ниже, но достаточно для задачи

### ADR-003: Telethon для Telegram
**Дата:** 2026-02-17
**Решение:** Userbot через Telethon
**Причина:** Нужен доступ к личным чатам менеджеров
**Риск:** Возможен бан аккаунта при агрессивном использовании

### ADR-004: Customer Health Scoring Model
**Дата:** 2026-02-17
**Решение:** Комплексный Health Score из 5 компонентов (Engagement, Sentiment, Operations, Financial, Relationship)
**Причина:** Проактивное выявление рисков оттока (churn) до того, как клиент уйдёт
**Референс:** NotebookLM use case от Zvi Shapira + Gainsight/ChurnZero best practices

### ADR-005: Sentiment Analysis Pipeline
**Дата:** 2026-02-17
**Решение:** GLM-4 для анализа тональности + тренд-анализ
**Альтернативы рассмотрены:** VADER (слишком базовый), Transformers fine-tuned (требует данных)
**Причина:** GLM-4 уже используется в системе, русский язык поддерживается

### ADR-006: RFM-based Engagement Scoring
**Дата:** 2026-02-17
**Решение:** Recency-Frequency-Monetary модель адаптированная под фулфилмент
**Референс:** Kortix-AI/Suna implementation
**Компоненты:** R = давность контакта, F = частота коммуникаций, M = объём отгрузок
